# 华为手环睡眠数据 → 自托管 MCP

本文只写**读者要做的事**。fork 相对上游的工程细节和代码位置见
[PATCHES.md](PATCHES.md)。

---

## 这是什么

让华为手环的睡眠、心率、步数数据，变成你的 AI 助手能直接读到的东西。

只要说一句「最近没怎么睡好」，它就可以直接主动看你实际的健康数据。

华为没有给个人用户提供方便的数据导出接口，Health Kit 开放平台也需要企业资质。
这套方案绕开华为云，直接从手环蓝牙同步原始数据，落到你自己的服务器或者 Android Health Connect。

**验证设备**：Huawei Band 10。Gadgetbridge 支持的其他华为设备原理相同。

链路很短，而且有两条出口：

```text
                         ┌── HTTPS ──> 你的服务器 ── MCP ──> ChatGPT / Claude / Codex / 其他任意客户端

手环 ──蓝牙──> 一个 APK ─┤
                         └── 写入 ───> Health Connect ──> 美国地区 Claude（Pro / Max、Android 14+；不用服务器）
```

默认走上面这条：手机负责从手环取数，再上传到自己的服务器，通过 MCP 给 AI 读取。

如果你只用美区 Claude，事情会简单很多：Claude 可以直接读取 Health Connect，因此不用 VPS、域名和 MCP 服务。你只需要完成 Step 1 安装 App、Step 2 连接手环，然后跳到最后的 Health Connect 一节。

Health Connect 不能直接读取华为手环。
手环 → 手机这一步仍然需要 Gadgetbridge，只是省掉了后面的自托管服务器和 MCP。

如果还想让 ChatGPT、Codex、自建 App 或其他 MCP 客户端读取同一份数据，就继续完成 Step 3 ～ 5。

# 快速开始

## Step 1 · 装 App

本文默认使用已经编译好的 APK，不需要 Android 开发环境。

你需要：

- 一台 Android 手机
- 一只 Gadgetbridge 支持的华为手环
- 如果走自托管：一台能运行 Node.js 的服务器

下载 APK 后直接从 Step 1 开始。

> **下载**：在 [Releases 页](https://github.com/xiaoyou5602/band-health-sync/releases) 下载最新版 APK；
> 每个版本的 SHA-256 与最低 Android 版本见对应 release 说明。

它是 [Gadgetbridge](https://codeberg.org/Freeyourgadget/Gadgetbridge) 的修改版
（AGPLv3，源码见文末）。桌面上显示为「健康数据」，包名带独立后缀，**跟官方版
Gadgetbridge 可以共存**，装了不影响你原有的。

如果你想自己修改或编译 App，构建方法放在文末的「自己构建」，需要 JDK 17 和 Android SDK 37。

## Step 2 · 连上手环

Huawei Band 10 是 **Gadgetbridge 上游原生支持**的，不靠任何修改就能连。上游
changelog 里有 `Initial support for Huawei Band 10`。

华为手环可以在**没有认证密钥**的情况下配对，但缺点是**手环会恢复出厂设置**，手环上的历史数据会全部丢失。
有认证密匙可以规避掉这点。

### 2.1 拿认证密钥

密钥就是你华为账号的 `userId`，从华为云空间的 cookie 里取：

1. 浏览器打开 <https://cloud.huawei.com>，登录你的华为账号
2. 按 `F12` 打开开发者工具
3. 切到「应用程序 / Application」标签
4. 左侧找到 「Cookie」→ 展开 → 选中 `https://cloud.huawei.com`
5. 找到名为 `userId` 的那一条，**复制它的 Value**

> 它是你的华为账号标识，不要贴到公开地方。

### 2.2 处理蓝牙抢占

- 认证密钥**只有在手环和华为运动健康处于连接状态时才有效**，否则 Gadgetbridge 会报
  **「认证密钥协商失败」**
- 但华为运动健康留在手机上，它又会**和 Gadgetbridge 抢蓝牙**，导致连接不稳定

解法：

利用「连接状态」和「App 是否在场」的时间差

1. **先**在华为运动健康里正常连接手环，确认连上了
2. **然后**卸载华为运动健康
3. **再**去 Gadgetbridge 做认证

卸载不会解除手环侧的绑定状态，所以密钥仍然有效；但抢蓝牙的进程没了。

配对完成后一般不建议再安装回华为运动健康，否则它可能继续抢占蓝牙。Gadgetbridge 本身支持华为 OTA，固件更新也不依赖官方 App。

### 2.3 配对

在 Gadgetbridge（「健康数据」）里：

1. 进「搜索设备」页面
2. **长按**扫描到的手环
3. 选「认证设置」
4. 选「华为账号」
5. 粘贴 2.1 拿到的认证密钥
6. **回到「搜索设备」页面，点击配对**
7. **在手环上点同意**
8. 完成

**初次认证走错入口是最常见的失败原因。**

- **必须打开 WiFi 和蓝牙**。认证要联网跟华为云校验密钥，网络连接要正确
- **必须从「搜索设备」页面走完整的绑定流程**。没连接成功前设备页面出现的手环卡片，点了也无法通过验证，反而会一直报错——那条路只适用于已经认证成功的复连。

认证成功后，手环里已有的历史数据会**全量保留并回传**，不丢任何数据。

### 2.4 连上之后需要检查和打开的

**配对以后需要将手环绑定为「陪伴设备」**：`调试→陪伴设备→选择并绑定`
不绑定陪伴设备的话，手环只能在 App 打开时正常工作。消息提醒、设置扩展都会不稳定。

系统经常杀后台会导致手表连接断断续续：`在软件权限中放开自启动/无限制省电策略`
GB 同步手表数据需手动打开:`设置→自动化→ 自动获取活动数据`

官方 Gadgetbridge 有个 bug：每次连接手环时，都默认会把手环里的「科学睡眠」自动关掉，导致手表无法记录睡眠。
本 fork 已经修了这个 bug。但如果你之前用官方版连过，可能已经被关掉了——去手环设置里
确认一下，关了就手动打开：
`设备设置 → 健康 → 华为 TruSleep / 科学睡眠`

剩下设置很多看自己的需求，譬如：可以在手环卡片的设备特殊设置页面修改自己的扩展，是否启用手机查找、心率自动检测、久坐提醒;在`设置 → 通知 → 单个应用列表区`可以调整能手表能收到哪些软件消息

## Step 3 · 架服务端

一个 Node 服务，约 360 行，Express + MCP SDK。需要 Node 20+。

```bash
git clone https://github.com/xiaoyou5602/health-mcp.git && cd health-mcp
npm install
```

生成两个 token（**用随机的**）：

```bash
openssl rand -hex 24   # 上传 token
openssl rand -hex 24   # 读取 token
```

配置写进 `.env`：

```bash
HEALTH_INGEST_TOKEN=刚才第一个        # 上传门锁，至少 16 字符，服务端强制
HEALTH_MCP_ACCESS_TOKEN=刚才第二个    # 读取门锁，留空则任何人可读
HEALTH_DATA_DIR=/var/lib/health-mcp  # 数据目录
HEALTH_MCP_PUBLIC_URLS=https://你的域名  # 用于 Host 头校验，多个用逗号分隔
HEALTH_MCP_PORT=3100
HEALTH_MCP_HOST=127.0.0.1             # 只监听回环，公网由反代/Tunnel 转进来
```

两个 token **必须不一样**：上传的那个在手机 App 里，读取的那个在 AI 客户端里，
泄露一个不至于连带另一个。

启动：

```bash
node health-server.js
```

跑通之后建议配成 systemd 服务，别用 `nohup` 裸跑——手机会持续往这里写数据，进程死了
不会有人通知你。

公网入口用 Caddy / Nginx 反代，或者 Cloudflare Tunnel（不用买公网 IP，也不用开端口）。
**必须上 HTTPS**：token 和健康数据都在明文 body 里。

数据按天落盘，同一天重复上传会自动合并，不会覆盖已有记录：步数取较大值、心率按时间戳去重、时间跨度重叠的睡眠 session 只保留最完整版本。所以重复上传、或者你手动补传历史，都不会把数据搞乱。

装好之后先自测一下，确认服务活着：

```bash
curl https://你的域名/healthz
```

返回 `{"ok":true,...}` 就行。

## Step 4 · 把 App 连到你的服务器

在「健康数据」里：**设置 → 外部集成 → 自托管健康同步**

1. **服务器地址**：填域名就行，比如 `health.example.com`。`/api/health` 会自动补上，
   `https://` 也会自动补。填完那一行会显示补全后的完整地址，对一眼。
2. **访问令牌**：填 Step 3 设的上传 token
3. **设备**：勾上你的手环
4. **启用上传**：打开。**这一下会把初始同步起点冻结成今天 00:00**——如果你以前用别的设备
   写过数据，这样不会把旧时段反向重放一遍弄乱历史
5. 点**立即上传**，看「上次上传」那一行

那行会直接告诉你结果：

| 显示                   | 意思                       |
| ---------------------- | -------------------------- |
| `已上传 N 天`          | 成功                       |
| `服务器地址或令牌没填` | 有一项空着                 |
| `没有选择设备`         | 第 3 步漏了                |
| `失败：HTTP 401`       | 令牌跟服务端的对不上       |
| `失败：HTTP 404`       | 地址不对，或者服务没跑起来 |

**「取数后立即上传」默认开着**，之后手环每次送来新数据都会自动上传。可选关闭或者自定义间隔

> 令牌是明文存在 App 偏好里的，跟 Gadgetbridge 其他设置一样。共用设备上别用。

## Step 5 · 接到 AI

服务暴露两个 MCP 工具：

- `health_read(days, type)` — 读原始记录，`type` 可选 `steps` / `heart_rate` / `sleep` / `all`
- `health_summary(days)` — 按天的汇总，适合日常问答

MCP 入口为 `https://你的域名/mcp`（Streamable HTTP）。

**Claude**：设置 → Connectors → 添加自定义连接器，填上面那个 URL。如果你设了读取
token，在请求头里加 `Authorization: Bearer 你的读取token`。

**ChatGPT / Codex**：在 MCP 服务器配置里填同一个 URL 和同一个 Bearer 头。

**命令行验证**（配之前先确认服务能应答）：

```bash
curl -X POST https://你的域名/mcp \
  -H "Authorization: Bearer 你的读取token" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
```

配好之后可以问自家机：

> 我这周平均睡几个小时？
> 最近我的深睡状态怎么样？
> 我今天什么时候心率最高？

## 可选 · Health Connect

Health Connect 是安卓的系统级健康数据中枢，负责在 App 之间中转数据。可以不架服务器，也不用配置 MCP。

本 fork 负责把华为手环的数据写进 Health Connect，Claude 再通过自己的 Health Connect 功能读取。两者不是同一个集成：本 fork 只是补上华为手环 → Health Connect 这一段

在「健康数据」里：

- 设置 → 外部集成 → Health Connect → 启用
- 设备选择里勾选你的手环
- 打开「设备同步后进行同步」
- **设一个初始同步起点**（比如今天 00:00）

这条路目前只适用于美国地区的 Claude Pro / Max；具体条件以[Claude 官方说明](https://support.claude.com/en/articles/11869629-use-claude-with-android-apps)为准。

# 常见问题

**点设备卡片连不上 / 初次认证一直静默失败**
初次认证**必须**从「搜索设备」页面走完整流程（Step 2.3），点设备卡片那条路只适用于已经
认证过的复连。设备删掉重来时尤其容易踩——直觉都是去点卡片。

**配对失败，但流程和顺序都对**
检查 WiFi 是不是开着。认证要联网跟华为云校验密钥。

**配对时提示「认证密钥协商失败」**
密钥只有在手环和华为运动健康处于连接状态时才有效。按 Step 2.2 的顺序来：先用华为运动
健康连上 → 卸载它 → 再去 Gadgetbridge 认证。顺序错了就会报这个。

**手环被恢复出厂了，数据全没了**
在没有认证密钥的情况下直接配对会触发恢复出厂。先拿密钥（Step 2.1），别急着点配对。

**连接总是断断续续**
华为运动健康还装在手机上的话，它会和 Gadgetbridge 抢蓝牙。检查自启动/省电策略有没有关

**装了之后手环睡眠分期没了 / 变差了**
八成是科学睡眠被关掉了。本 fork 修了这个 bug，但如果你之前用官方版连过，得去手环设置里
手动打开一次。

**上传显示 404**
地址不对。App 会自动补 `/api/health`，所以 404 通常意味着域名写错了、或者服务没起来。
先 `curl https://你的域名/healthz` 确认服务活着。

**上传显示 401**
令牌跟服务端配的那个对不上。注意别把「上传 token」和「读取 token」搞混了。

**步数和心率同步上去了，睡眠没有**
睡眠会先等一小段「定型」——手上要有「睡眠结束之后约 10 分钟」的数据才上传，免得把还没睡完的半截夜送上去。所以醒来动一动、等 App 下次取数（连上手环或到点自动取），这一夜就上去了。迟迟没有的话，多半是醒后还没取过数，没有新数据可发。

服务端按时间重叠去重、只保留最完整的那版，所以一夜就算先短后长分两次送，也是覆盖而不是并存，不会被重复计算。

**昨晚 11 点睡今早 7 点醒，算哪天的？**
算今天的。睡眠按**醒来日期**归属，App 里、桌面组件里、服务器上都是同一套算法。

**睡眠时长跟手环 App 对不上，少了一点**
睡眠总时长**不计中途清醒**。清醒阶段单独统计，不算进总时长。

**手动补传多日历史返回 413**
上传 body 超了默认上限。服务端默认给到 16 MB，如果你改小过就是这个原因。

# 跟上游 Gadgetbridge 有什么不一样

不看也能用。这里只说结论，工程细节和代码位置在 [PATCHES.md](PATCHES.md)。

| 改动                             | 为什么                                                                                                         |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **修华为「科学睡眠」被静默关掉** | 上游每次连接都会向手环下发「关闭」，而不是「不改动」。这条影响所有用 Gadgetbridge 连华为设备的人，跟自托管无关 |
| **加了自托管健康同步**           | 就是 Step 4。上游没有这个功能                                                                                  |
| **拿回 INTERNET 权限**           | 上游刻意不要这个权限，联网功能全走一个独立的 Internet Helper App。直传要是也走它，就等于又多装一个 App         |
| **独立包名和显示名**             | 好跟官方版共存                                                                                                 |
| **取数后立即导出 / 上传**        | 上游只有周期任务兜底，延迟是小时级                                                                             |

关于 INTERNET 权限说明白一点：它是**安装期权限**，装的时候自动给，不会弹窗问你，也不会
出现在运行时权限列表里。App 用它做且只做一件事——把你的数据 POST 到**你自己填的那个
地址**。不填地址、不开开关，它一个字节都不会发。源码是 AGPLv3 的，可以自己查。

# 附录 · 自己构建

```bash
./gradlew assembleMainlineDebug --no-parallel
```

JDK 17，Android SDK / build-tools 37。产物在
`app/build/outputs/apk/mainline/debug/app-mainline-debug.apk`。

覆盖安装用 `adb install -r`，**不要**靠卸载或清数据解决安装失败——那会丢掉配对信息和
历史数据。

全部改动都在这个仓库里（AGPLv3 要求提供源码）：

<https://github.com/xiaoyou5602/band-health-sync>
